## What this means for you

From the postings I could verify:

- FamApp names **Python and Go** for backend and infrastructure work, plus **Kafka** for events, and expects you to use AI coding tools.
- slice's backend posting uses **Node.js** frameworks.

What both companies ask about is the same set of ideas: APIs, databases, events, observability and running systems at scale. Those ideas carry over between languages, and they're what the PocketPay blocks teach.

## The options for PocketPay

| Option | Good for you because | Cost |
|---|---|---|
| **FastAPI + Pydantic + psycopg 3 (chosen)** | You already know FastAPI. Plain SQL through psycopg keeps transactions and locks visible. One language for the backend, the AI agent and the evals. | No hidden magic to lean on: you write the SQL and transactions yourself. |
| FastAPI + SQLAlchemy | You already know FastAPI, so all your attention goes to payments ideas. Python matches FamApp's postings. | You set up migrations and transactions yourself, which is extra learning. |
| Django + DRF | Django appears in FamApp's SRE posting. [Database transactions](https://docs.djangoproject.com/en/stable/topics/db/transactions/) are built in through `transaction.atomic()`. | A new framework on top of new payments concepts, on a tight weekend. |
| Node.js (Express) | Matches slice's posting. | Moves you away from Python, which is your strength and FamApp's. |

## Decision: Python everywhere, with FastAPI, Pydantic and psycopg 3

You want to put understanding the concepts first, and you see yourself as an AI Engineer more than a backend engineer. So PocketPay is all Python:

- **Payments API in FastAPI**, which its docs describe as a web framework "for building APIs with Python based on standard Python type hints".[^fastapi] **Pydantic** checks request data, for example that an amount is a whole number above zero.[^pydantic]
- **PostgreSQL with plain SQL through psycopg 3**, a "PostgreSQL database adapter for the Python programming language".[^psycopg] You still write `BEGIN`, `FOR UPDATE` and `COMMIT` yourself, exactly as on the ledger pages. We chose it over the SQLAlchemy ORM because an ORM writes that SQL for you, and seeing it is the point right now.
- **Async throughout.** Endpoints are `async def` and use psycopg's async API, so the server keeps serving other users while one request waits on the database or an LLM. See [Async Python, from scratch](/day-1/async-python).
- **MCP server in Python.** Python is a Tier 1 official MCP SDK.[^mcp]
- **AI support agent and evals in Python with LangGraph**.[^langgraph]

FamApp's [infra posting](https://jobs.lever.co/fampay/9b8d4eaa-cd29-4aec-8dcc-a33fd78d5657) asks for "Python or Go", so Python covers what it asks for.

## Decisions so far

- **Experience:** 6 to 8 months of backend, comfortable with FastAPI. The notes explain payments ideas from scratch.
- **Product:** PocketPay, API only. No web UI.
- **Backend:** Python: FastAPI + Pydantic + psycopg 3 (plain SQL, async) + PostgreSQL, managed with uv. **AI layer:** Python for LangGraph, the MCP server and evals.
- **Notes site:** Vite + React + MDX + Tailwind, the app you're reading now. Hosting comes later.
